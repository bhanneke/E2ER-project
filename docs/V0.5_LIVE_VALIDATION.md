## Run 1 — Empirical hallucination → REJECTED at the verify_numbers gate

**Goal:** confirm the drafter cannot land a paper whose tables cite
numbers absent from the analyst's source JSON.

**Scenario shape:** an empirical RQ where the available data is
narrow enough that the drafter is tempted to invent supporting
statistics (the `a6182f08` failure mode).

```bash
e2er run \
  "Does liquidity concentration in Uniswap v3 affect price discovery
   during the first 24 hours after each pool's launch?" \
  --methodology empirical \
  --mode single_pass \
  --max-cost 5.00
```

**Expected outcome.** The pipeline runs through data_architect →
data_analyst → econometrics → paper_drafter, then hits
`_run_review_phase`. The verify_numbers gate scans `paper_draft.tex`
against `summary_statistics.json` / `estimation_results.json` /
`robustness_results.json`. **If the drafter hallucinated**, the gate
fires:

- Status transitions IN_PROGRESS → REJECTED.
- `paper_draft.tex.applied.diff` is NOT created (no reviewers ran).
- `number_verification.json` exists at the workspace root with
  `passed: false` and a non-empty `mismatches` array.
- The `papers.last_error` row carries a "verify_numbers: N critical
  mismatch(es)…" string.
- Reviewer artifact files (`review_*.md`) are NOT present.

**If the drafter behaved**, the pipeline proceeds through reviewers
and completes normally. That's also a valid v0.5 outcome — it means
the gate's graceful-skip path is correctly not blocking honest runs.
**Important to capture in either case:** the contents of
`number_verification.json` and whether reviewers spawned.

**Verification commands:**

```bash
PAPER=<paper_id_from_e2er_run>
WS=$(curl -s http://127.0.0.1:8280/api/papers/$PAPER | jq -r .workspace)

# Final status
curl -s http://127.0.0.1:8280/api/papers/$PAPER | jq '{status, last_error}'

# Verification report — must exist regardless of pass/fail
cat $WS/number_verification.json | jq '{passed, matched, mismatched, critical_count: (.mismatches | map(select(.severity == "critical")) | length)}'

# Did reviewers run? If gate fired, this list should be empty.
ls $WS/review_*.md 2>/dev/null || echo "no reviewer files (gate fired)"

# Resume path works (REJECTED is resumable)
# Only if status == "rejected":
# 1. Manually fix the drafter's hallucinated table OR
# 2. Re-write summary_statistics.json with the values the drafter cited
# 3. POST /resume — should re-enter REVIEW and proceed
```

**Pass criteria:**
1. Pipeline does not crash (no FAILED).
2. `number_verification.json` is present and parseable.
3. If `passed: false`, status is REJECTED and reviewers did not run.
4. If REJECTED, resume after revising artifacts succeeds.

## Run 2 — Theoretical → data_reviewer + replication skipped

**Goal:** confirm methodology-aware routing actually skips the two
wasteful specialists, and that the resulting cost is materially lower
than an empirical run on the same backend.

**Scenario shape:** a pure-theory RQ with no empirical claims. Mirrors
the `cbe8048f` setup.

```bash
e2er run \
  "Characterise the equilibrium price impact of MEV searchers
   competing over a single block's transaction ordering, assuming
   common-value private signals about pending order flow." \
  --methodology theoretical \
  --mode single_pass \
  --max-cost 5.00
```

**Expected outcome.**

- `theory_specialist` dispatched (writes `model_spec.md`).
- `data_architect`, `data_analyst`, `econometrics_specialist` NOT
  dispatched (the strategist's methodology routing handles this).
- Reviewer panel = 5 specialists (not 6) — `data_reviewer` absent.
- Replication phase early-returns with the log line
  "Skipping replication phase for paper X (methodology=theoretical)".
- No `replication/` directory in the workspace.
- Total cost should be ~30-40% lower than a comparable empirical run
  on the same backend.

**Verification commands:**

```bash
PAPER=<paper_id_from_e2er_run>
WS=$(curl -s http://127.0.0.1:8280/api/papers/$PAPER | jq -r .workspace)

# Status and methodology persisted
curl -s http://127.0.0.1:8280/api/papers/$PAPER | jq '{status, methodology}'

# theory_specialist ran
test -f $WS/model_spec.md && echo "✓ model_spec.md present"

# data_reviewer did NOT run
test ! -f $WS/review_data.md && echo "✓ data_reviewer skipped"

# Other reviewers DID run
ls $WS/review_*.md | grep -v review_data | wc -l   # expect 5

# Replication packager skipped — `_best_effort_finalize` always
# exports the audit trail (`audit_log.csv` + `data_queries.sql`)
# regardless of methodology, so the directory itself may exist with
# those two files. The real contract is that the packager's outputs
# (`estimation.py` + `README.md`) are absent.
test ! -f $WS/replication/estimation.py && echo "✓ replication_packager skipped"
test ! -f $WS/replication/README.md && echo "✓ replication README absent"

# Cost report
curl -s http://127.0.0.1:8280/api/papers/$PAPER/usage | jq .total_cost_usd
```

**Pass criteria:**
1. Paper reaches COMPLETED (no REJECTED, no FAILED).
2. `model_spec.md` exists.
3. `review_data.md` does NOT exist.
4. `replication/` directory does NOT exist.
5. Total cost < Run 1's data-phase cost (i.e. theoretical is cheaper).

## Run 3 — Budget exhaustion → PAUSED, resumable

**Goal:** confirm `BudgetExceededError` mid-run transitions to PAUSED
with a structured envelope, and that resume picks up correctly after
raising the cap.

**Scenario shape:** any empirical RQ submitted with `--max-cost`
deliberately too low (e.g. $0.50) to force the budget check to trip
mid-pipeline.

```bash
e2er run \
  "Empirical: does the Ethereum gas-fee market exhibit predictable
   intraday cycles around US trading-hours boundaries?" \
  --methodology empirical \
  --mode single_pass \
  --max-cost 0.50
```

**Expected outcome.**

- The pipeline runs the initial phase, then the next `check_budget`
  call trips `BudgetExceededError`.
- Status transitions to PAUSED (not FAILED).
- The API response: `{status: "paused", reason: "budget_exhausted",
  spent: <float>, cap: 0.5}`.
- `.pipeline_state.json` is persisted at the workspace root.
- `papers.last_error` carries "BudgetExceededError: spent $X.XX,
  cap $0.50".
- A `paused_budget` event is in the events table with `{spent, cap}`
  payload.
- **Resume:** POST `/api/papers/{id}/resume` with the same paper
  (after raising the cap via the API or `.env`) and the pipeline
  picks up at the first incomplete phase.

**Verification commands:**

```bash
PAPER=<paper_id_from_e2er_run>

# Final status + structured error
curl -s http://127.0.0.1:8280/api/papers/$PAPER | jq '{status, last_error}'
# Expect: status="paused", last_error contains "BudgetExceededError"

# Event log carries the structured payload
curl -s http://127.0.0.1:8280/api/papers/$PAPER/events | \
  jq '.[] | select(.event_type == "paused_budget")'

# State file preserved for resume
WS=$(curl -s http://127.0.0.1:8280/api/papers/$PAPER | jq -r .workspace)
cat $WS/.pipeline_state.json | jq '{completed_stages, current_stage}'

# Resume after raising the cap.
# IMPORTANT: the /resume endpoint does NOT read `max_cost_usd` from
# the POST body — it reads the cap directly from the papers row. So
# you must UPDATE the row first, then POST /resume with an empty body.
# (Discovered during 2026-05-20 live validation. Worth fixing as a
# follow-up: have /resume accept an optional `max_cost_usd` body
# parameter and persist it before re-firing the runner.)
PGPASSWORD=$DB_PASSWORD psql -h $DB_HOST -p $DB_PORT -U $DB_USER -d $DB_NAME \
  -c "UPDATE papers SET max_cost_usd = 15.00 WHERE id = '$PAPER';"
curl -X POST http://127.0.0.1:8280/api/papers/$PAPER/resume \
  -H "Content-Type: application/json" -d '{}'

# Wait, then check final status — should NOT have re-run completed phases
sleep 60
curl -s http://127.0.0.1:8280/api/papers/$PAPER | jq '{status, last_error}'
```

**Pass criteria:**
1. Status is PAUSED, not FAILED.
2. `last_error` row carries the budget message (not NULL — that's
   the `_update_status` fix shipped in this commit).
3. `paused_budget` event in the events table with structured payload.
4. After resume with higher cap, the pipeline does NOT re-run
   already-completed phases (idempotent resume).

## 2026-05-20 results (executed against 5e5b3e1)

Two papers + one resume covered all three v0.5 code paths. Run 1's
budget exhaustion at $5 happened to fire the PAUSED path early
(originally meant for Run 3), so a dedicated third paper wasn't
needed — the resume then confirmed the resume-from-disk behaviour.

| Run | Paper ID | Methodology | Outcome | What it validated |
|---|---|---|---|---|
| 1 | `234a11ea-6352-442d-b96b-f2d9301e55dd` | empirical, cap=$5 | PAUSED at 12 min, spent $6.29 | `BudgetExceededError → PAUSED` envelope; `last_error` preserved on the row; `verify_numbers` graceful-skip path (no source JSONs); full 6-reviewer panel ran (incl. `data_reviewer`) |
| 1 (resumed) | same | empirical, cap raised to $15 | COMPLETED in 2 min after resume | Resume-from-disk: only 1 new specialist call (`replication_packager`); initial + review phases correctly skipped; `last_error` cleared on transition to COMPLETED |
| 2 | `fd6bf64d-8b71-4fc6-bfda-aad78a6ab33e` | theoretical, cap=$10 | COMPLETED at 24 min, spent $5.55 | `theory_specialist` ran (`model_spec.md` 333 lines); `data_reviewer` skipped (5/6 reviewers ran); `replication_packager` skipped (no `estimation.py`); 13 specialist calls vs 15 for empirical |

### What was NOT directly exercised (and why that's OK)

- **`verify_numbers` REJECTED path.** Did not fire on either run
  because the analyst + econometrics specialists didn't produce the
  source JSON contract (`summary_statistics.json` etc.). The gate
  correctly fell through its graceful-skip path. This is the
  documented limitation in `V0.5_PLAN.md` — the gate activates once
  the specialist prompts are updated to emit the JSON files.
  Regression coverage: `tests/pipeline/test_verify_numbers.py` (32
  tests) + `tests/pipeline/integration/test_rejected_status.py`
  (`test_verify_numbers_critical_mismatch_yields_rejected`).
- **`HARD_REJECT → REJECTED` path.** The review aggregator's
  HARD_REJECT verdict didn't trigger on either run (reviews were
  positive enough). Regression coverage:
  `test_hard_reject_verdict_yields_rejected_not_failed`.

Both are mocked-test-covered; live-fire validation deferred until a
real run produces the conditions.

### Findings from the live runs (logged for follow-up)

1. **`/resume` ignores `max_cost_usd` in the POST body.** The
   endpoint reads the cap from the DB row. Workaround: UPDATE the
   row before POSTing. Should be fixed in a v0.5.1 patch — small
   change to `resume_paper` in `src/api/app.py` to accept an
   optional body parameter and persist it.
2. **Runbook nit on the replication-skip check.** `_best_effort_finalize`
   always creates `replication/audit_log.csv` and `data_queries.sql`
   regardless of methodology. The v0.5 contract is that the
   `replication_packager` specialist (which emits `estimation.py` and
   `README.md`) is skipped — not the audit trail. Runbook updated.
3. **Cost reporting is synthetic on the CLI backend** but accurate
   in shape. `cost_is_estimate: true` flag works; actual cost was $0
   (Max plan) but the estimate of $6.29 / $5.55 tracks token usage
   at Sonnet rates and correctly triggers budget gates.

## Failure modes (and what they tell you)

| If you see... | It means... | Action |
|---|---|---|
| Run 1: pipeline crashes with FAILED, not REJECTED | The verify_numbers gate didn't catch a hallucination, OR the gate caught it but the runner still transitioned to FAILED (regression). | Read `last_error` and check the events table. If the gate fired, `_run_review_phase`'s REJECTED return path is broken. |
| Run 1: no `number_verification.json` | The gate didn't run at all. | Check that `paper_draft.tex` exists and that `_run_review_phase` is actually being entered. The skip-on-missing-draft branch may be tripping. |
| Run 2: `review_data.md` exists | Methodology routing didn't take effect. | Verify `papers.methodology` is `theoretical` in the DB. If yes, `_reviewers_for_methodology()` may not be reading from `self._methodology` correctly. |
| Run 2: `replication/` directory exists | Same as above, on the replication branch. | Check `_run_replication_phase`'s early-return condition. |
| Run 3: status FAILED, not PAUSED | The new `except BudgetExceededError` branch isn't catching the exception. | Check that `BudgetExceededError` is imported in runner.py and the branch ordering puts it before generic Exception. |
| Run 3: `last_error` is NULL | The `_update_status` fix for PAUSED isn't applied. | Confirm the `preserve_error` set includes PAUSED. |
