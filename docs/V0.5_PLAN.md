## Motivation: what v0.4.5 live tests uncovered

| Paper | Methodology | Failure mode | Cost burned before catch |
|------|------|------|------|
| `a6182f08` | empirical | Drafter cited `"log realized variance falls by 0.41 ($t=-3.9$)"` — numbers the analyst's 14 CSVs cannot produce | 6 reviewers ran (~$X) before `technical_reviewer` returned HARD_REJECT (score=3) |
| `cbe8048f` | theoretical | `data_reviewer` ran on an empty data contract (~$0.34); `replication_packager` ran on a paper with no replication artifacts (~$0.43) | Specialist budget for both roles, fully wasted |
| `eea5379b` | empirical | Pipeline finished but `BudgetExceededError` mid-run terminated as `FAILED`, indistinguishable from a crash | Workspace orphaned; resume path unclear |

Common thread: the pipeline detects problems **after** spending tokens
on artifact production that the problem invalidates. v0.5 moves the
detection earlier, makes the verdicts mechanical, and distinguishes
recoverable from terminal failures.

## The four changes (all in working tree)

### 1. `verify_numbers` — programmatic anti-hallucination gate

**New file:** `src/core/pipeline/verify_numbers.py` (357 lines, ported
from v1's equivalent module, adapted to the v3 flat-workspace layout).

**What it does.** Before reviewers run, scan every number inside
`\begin{tabular}...\end{tabular}` blocks in `paper_draft.tex` and
match each one against the flat dotted-key map of values pulled from:

- `summary_statistics.json` (data_analyst)
- `estimation_results.json` (econometrics_specialist)
- `robustness_results.json` (econometrics_specialist, optional)
- `figure_spec.json` (optional)

**Matching rules** (`_values_match`, `verify_numbers.py:142`):

- Signs must match (zero is sign-agnostic).
- Integer source values ≥10 must be exact.
- Decimals: `|draft − source| ≤ tolerance · max(1, |source|)`, tolerance
  defaults to 0.5%.

**Severity rules.** If no exact match, find the closest source value:
- relative error >10% → `critical` (HARD-REJECT trigger)
- relative error ≤10% → `major`
- no value within 50% → `unverifiable` (likely a derived quantity, not
  a mismatch — counted but does not gate)

**Wiring.** `runner._run_review_phase` calls `verify_and_save(draft_path,
workspace)` before transitioning to REVIEW. If `report.critical_mismatches`
is non-empty, the runner writes a structured error summary, calls
`_update_status(REJECTED, ...)`, and returns `REJECTED` — reviewers
never spawn.

**Graceful skip.** If none of the source JSON files exist, the gate
emits a warning and passes (`skipped_reason` is recorded in
`number_verification.json`). This protects papers from before the
specialist contract was tightened; once the analyst + econometrics
prompts reliably emit the JSON files, the gate becomes effective with
no further code change.

**Persisted artifact.** Every run writes `number_verification.json` at
the workspace root, regardless of outcome. Reviewers (when they do
run) and the dashboard can read it as ground truth.

**Cost.** Deterministic, no LLM calls, sub-second.

### 2. Methodology-aware phase routing

**Files touched:** `src/api/app.py`, `src/core/strategist/runner.py`.

`PipelineRunner.__init__` now accepts `methodology: str = "empirical"`,
plumbed through `_run_pipeline` and `resume_paper` in `app.py`. The
`papers.methodology` column already exists from v0.4 — the runner just
hadn't been reading it.

Two behaviours change for `methodology == "theoretical"`:

- **`_reviewers_for_methodology()`** filters `REVIEWER_SPECIALISTS`,
  dropping `data_reviewer`. Theoretical papers have no data contract;
  paper `cbe8048f` proved the reviewer just emits a generic stub.
- **`_run_replication_phase()`** early-returns with a log line. No
  replication artifacts exist for a pure theory paper.

Empirical papers are unchanged — same 6-reviewer panel, same
replication packaging.

### 3. `REJECTED` ≠ `FAILED`

**File touched:** `src/core/strategist/state.py`.

New status `PaperStatus.REJECTED`, distinct from `FAILED`:

- `FAILED` = pipeline crashed (uncaught exception, infra problem).
- `REJECTED` = the pipeline ran successfully and the review gate (or
  `verify_numbers`) said the work product fails quality bar.

**Transitions added:**
- `IN_PROGRESS → REJECTED` (verify_numbers critical mismatch path).
- `REVIEW → REJECTED`, `REVISION → REJECTED` (HARD_REJECT,
  MECHANISM_FAIL).
- `REJECTED → {IDEA, CANCELLED, IN_PROGRESS, REVIEW, REVISION}` — the
  operator can revise the source artifacts and POST `/resume` to
  re-enter at the appropriate phase, or restart from IDEA.

`_run_revision_phase`'s HARD_REJECT / MECHANISM_FAIL branch updated to
emit REJECTED instead of FAILED.

### 4. `BudgetExceededError → PAUSED`, resumable

**Files touched:** `src/core/strategist/runner.py`,
`src/core/strategist/state.py` (semantic update to PAUSED's docstring).

New `except BudgetExceededError as be` branch in `PipelineRunner.run()`,
sitting alongside the existing `CircuitBreakerError` handler:

1. Persists state (`state.save(self._workspace)`).
2. Logs `paused_budget` event with `{spent, cap}` payload.
3. Sets status to `PAUSED`.
4. Returns `{"status": "paused", "reason": "budget_exhausted", ...}`
   so the API can render the structured outcome.

The operator raises `--max-cost` and POSTs `/api/papers/{id}/resume`;
the existing resume-from-disk logic picks up at the first incomplete
phase.

`PAUSED`'s docstring updated to describe both halt sources
(circuit-breaker AND budget) — the existing transition table already
permitted everything we need, so VALID_TRANSITIONS only changes for
REJECTED.

## Why these four together

They're not arbitrary — each is the **earliest mechanical signal** for
one of the four failure modes the live tests surfaced:

| Failure mode | Earliest detection | Mechanism |
|---|---|---|
| Drafter invents numbers | After draft, before review | `verify_numbers` (deterministic) |
| Wrong specialists run | At request time, before dispatch | `methodology` plumbed to runner |
| Quality reject vs crash | At terminal status assignment | `REJECTED` enum |
| Budget exhaustion mid-run | At budget check, before next dispatch | `PAUSED` + structured return |

All four follow the same pattern: **detect mechanically, distinguish
from generic failure, preserve enough state to resume.** This is the
deterministic-process discipline from the broader codebase applied to
the pipeline's verdicts.

## Architecture invariants v0.5 adds

To carry forward into the invariants list in `docs/NEXT_STEPS.md`:

1. **`verify_numbers` runs BEFORE the review phase.** Pinned by the
   runner integration test. Reverting to "reviewers detect
   hallucinations" re-introduces the multi-reviewer-wasted-spend bug.
2. **`PaperStatus.REJECTED` is distinct from `FAILED`.** Pinned by the
   transition test. Conflating them re-introduces the v0.4.5 resume-path
   ambiguity.
3. **`BudgetExceededError` does not terminate as FAILED.** Pinned by the
   budget-paused test. Reverting drops the workspace into an orphaned
   state.
4. **`methodology` is read from the DB on every dispatch path** —
   `_run_pipeline` and `resume_paper` both must pass it through.
   Otherwise theoretical papers silently revert to the empirical pipeline.
