# v0.9 plan — from `pip install` to a paper you trust

**Status:** active design doc (2026-05-31). Supersedes the deleted module-seam
draft. Built around the **user journey**, not internal architecture: the
ordering and scope falls out of what a real user needs at each step from
install to a paper they can defend.

## Where we are
- **v0.8.1 shipped to PyPI**, live-validated: OpenAlex search works (the null
  bug found+fixed in the code review is gone live), yfinance reaches the tool
  loop, `read_reference` extracts a real OA PDF, Zotero pulls 1,994 items.
  The only red was environmental (Allium credits).
- Both lanes are registry-pluggable; structured GitHub issue forms exist for
  "I want this data source / lit provider"; `LOCAL_DATA_DIR` now supports
  comma-separated roots, recursive walk, and local PDFs.
- Release process is mechanical + idempotent (workflow owns release creation +
  PyPI publish). No more manual missteps.

## The journey, and where it breaks today

| Step | What the user needs | Today's gap |
|------|---------------------|-------------|
| 0. Install | `pip install e2er` works | ✓ (0.8.1 on PyPI; install path verified) |
| 1. Configure | Get to a **$0** working setup fast | `e2er init` exists; doesn't *verify* the backend actually answers a call |
| 2. "Am I ready?" | A preflight that says "you're good" before spending a run | ✗ **no `e2er doctor`** — `live_check.py` exists for us, not for the user |
| 3. First paper | Succeeds end-to-end, no surprise bill, works with **zero** data/lit config | ⚠️ the zero-config theoretical/literature paper has never been live-validated end-to-end |
| 4. Trust the output | **No hallucinated citations**; clear "what's real vs assumed" | ✗ numbers are verified; **citations are not** |
| 5. See / recover | A showcase to look at; clear pause→resume | ⚠️ no `examples/showcase/` from a real run |

**The biggest gaps** — preflight, citation integrity, and a real end-to-end
proof — are exactly what v0.9 should close. Adding more data providers is not.

## Milestones (execution order)

### M1 — `e2er doctor` (user-facing preflight)
Productize `scripts/live_check.py` as a first-class CLI command. After `e2er
init`, the user runs `e2er doctor` and sees:
- backend reachable + a free `$0` ping where possible (Claude Code CLI / Codex /
  Gemini auto-detect; for keyed backends, a tiny test call gated behind the
  user's choice);
- skill files installed;
- DB OK (SQLite auto-init or Postgres reachable);
- configured data + literature providers reachable, with a one-line "what this
  paper would have access to";
- a clear final verdict (✅ ready / ⚠️ partial / ❌ blocked + what to fix).

Output is human-readable; JSON with `--json` for scripting. Live-check stays
as the dev harness; `e2er doctor` is the user surface.

### M2 — Reference-integrity gate
The biggest credibility killer for an AI paper tool is hallucinated citations.
Mechanical, deterministic gate (pattern: `verify_numbers`):
- Parse every `\cite{key}` and `\bibitem` from the draft.
- For each, verify it resolves to a real paper — OpenAlex by DOI first, then
  fallback to title+year against OpenAlex / Semantic Scholar / Crossref.
- Hard-block finalization on unverifiable references; emit a structured
  `citation_integrity.json` report with each cite's status, source, and the
  verifier hit.
- Pairs with a tiny coverage report: cited keys that aren't in the
  bibliography, and bibliography entries that were never cited.

This now leans on M1's literature reach being solid; **F2 below** strengthens
that further.

### M3 — Strengthen open-access full-text reach
The live-validation finding: Zotero PDFs often live outside Zotero cloud
storage, so the Web API can't serve them. The reliable path is open-access
resolution by DOI — which today goes through OpenAlex's `oa_url`. Broaden it:
- **Unpaywall** resolver (needs a polite-pool email; no key) — best
  coverage for OA full text.
- **Crossref** resolver (keyless) — fills more DOIs.
- Optional **CORE** later, if needed.
Plug into the existing `doi_fetch_sources` chain in the literature registry.
Caches per paper run so repeated resolutions of the same DOI cost one request.

### M4 — End-to-end paper run on the new features
We've validated the integration layer (M1 will keep doing so), but never a
*full paper* in anger on v0.8+. Pick a research question that exercises:
- **fetch_data** (yfinance — keyless, deterministic),
- a reference library (Zotero or local `.bib`),
- **read_reference** by DOI (the OA path that M3 broadens),
- the **reference-integrity gate** from M2.
Run via the **Claude Code CLI backend ($0)** so cost isn't a constraint.
Capture the failures honestly; iterate. This is the gate on calling v0.9 ready.

### M5 — Showcase example
Drop the M4 paper into `examples/showcase/` with: generated PDF, review
bundle, citation-integrity report, replication package. Lets a new user see
what "good" looks like before spending a run. Link from README's
"What you get" section.

## Demand-driven (NOT v0.9 — open the issue form)
The new issue forms (`data_source_request.yml` / `literature_provider_request.yml`)
are the front door. We build providers when a real user asks. Likely candidates
when they do:
- Data: CoinGecko, Dune / Flipside, WRDS, ECB / World Bank / IMF, Census / BLS.
- Literature: Citavi (M4 of the old plan), Mendeley, Paperpile.

## Explicitly deferred
- **App container** — functionality first; pluggable modules already let an
  app wrap them later.
- **Per-paper reference-library cache** — performance, not journey-critical;
  defer until measurable.
- **Live nightly CI** for `live_check` — nice-to-have; skip unless flakes hurt.

## Open decisions (resolve as we start each milestone)
- **M1**: which checks live in `doctor` by default? (Backend $0-ping, skills,
  DB, configured providers. Keep risky $$ checks behind a flag.)
- **M2**: hard-block vs warn-only on unverifiable cites? DOI-only or fuzzy
  title+year (more recall, more false positives)?
- **M3**: resolver order (Unpaywall → Crossref?); polite-pool email
  configuration (same as OpenAlex's `mailto`).

## Suggested minimum vs full v0.9
- **Minimum v0.9** ("install → trust" loop closed): **M1 + M2 + M4 + M5**.
- **Full v0.9**: + **M3** (broader OA reach — closes the Zotero-storage gap).

## Invariants (don't regress)
- `PaperMetadata` / envelope contracts stay the lane contracts.
- 5 Allium guardrails fire on every warehouse query.
- Lane-tagged PRs, CHANGELOG entries per `AGENTS.md`.
- `mypy` + venv test suite before pushing (CI runs both).
- The standardized release flow: bump both files → CHANGELOG cutover → PR
  dev→main → tag from main → workflow owns release+PyPI. No manual
  `gh release create`.
